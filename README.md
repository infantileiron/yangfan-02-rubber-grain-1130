# 屿垫再材·地垫色粒试配

从已通过质检的再生橡胶批次里，找出可沿用的四色试配记录。

模拟团队为 屿垫再材收配组，21 人，负责两条再生橡胶拼花地垫生产线的收料、称重试配和样板交接。。打样师从纸本配料记录和旧试片里翻选可用配方，把称重改动手写到试配卡，再交给品控核对批次。

- 历史批次以不同总克数登记，直接比较波动会把同一配方误判为不同。
- 低占比浅粒改变地垫斑点外观，直接拿百分点比较容易掩盖相对变化。
- 不同胶粒基材和磨耗不通过的配方需要回避，翻阅试片很难及时排除。

归档试片的实际称重单、品控验收结论，以及接单台提供的目标四色配比。 打样班根据同基材合格记录安排人工称样，品控以新试片复测色差和磨耗。

## 业务模块

| 模块 | 工作内容 | 核心实体 |
|---|---|---|
| 称重档案 | CSV 校验、预览实测字段、以完整数据内容的 SHA-256 去重、追溯版本和下载原始数据；历史归档须带母批号 | 数据版本 |
| 近邻校准 | 分基材按母批留出交叉验证选近邻数、留母批盲评并对比默认 3 近邻，验收通过后发布版本 | 校准版本 |
| 试配单 | 按版本与领域参数创建计算单，由独立进程计算；从排队、成功或失败状态追溯 | 计算单 |
| 配方参考 | 按业务字段查看度量、比较与排序，下载计算结果；可查所用档案、近邻数与盲评误差 | 计算单及其结果 |
| 称样交接 | 对结果样本作签发或暂缓，记录理由，导出选中样本并查看审计时间线 | 交接记录 |

## 算法及口径

**中心化对数比变换（CLR）与 Aitchison 最近邻**。输入为炭黑、陶红、沙黄、米白四种胶粒的实称克数，最小可检测重量为 0.01 g，未检出填 0。先把每行闭合成比例，把秤未检出的零值按至多 0.05% 替代并按比例缩放其他组分，再取各比例的对数减去其均值。CLR 向量的欧氏距离即 Aitchison 距离。每个目标只匹配基材相同且质检合格的历史批次，所有近邻坐标等权平均后经逆变换得到参考中心。取合格历史样本在同基材内的留一最近距离第 90 百分位，作为是否需要单独复测的距离参考。目标配方调量按最大余数法分配到整克。候选缺失称样重量、配比总量为零、历史缺少母批号或验收结论、记录编号重复或合格历史不足以覆盖指定近邻数时，任务返回具体原因。

**母批留出与近邻数校准。** 同桶胶粒分装会产生多个批次号，这些子批配比几乎相同，若按批次随机留出，同桶其他子批仍在近邻候选里，会显著高估推荐准度。因此所有历史归档必须登记母批号，校准与评估以母批为最小留出单位：

1. 每个基材单独校准。先选出合格子批最多的一个母批作为盲评母批，该母批的全部子批整体退出选参和近邻候选；
2. 在其余母批上做按母批留出的交叉验证，对 1–8 的每个近邻数计算**四色配比误差**（炭黑、陶红、沙黄、米白四个组分百分点绝对误差的均值），取误差最小的近邻数（并列取较小值）；
3. 盲评时用选出的近邻数与默认 3 近邻，在**同一批盲评样本**上比较误差；盲评误差不高于默认口径才算通过，否则该基材标记为「盲评未通过」，不发布、不影响线上；
4. 发布还要求校准所用档案是当前最新称重档案。补录称重档案期间没有新版本通过验收，推荐继续沿用旧版默认 3 近邻；验收失败时旧版保持发布；
5. 每个基材至多一个已发布版本，发布在数据库事务内原子切换，唯一约束保证并发发布只有一个胜出。

试配单执行时按基材读取已发布校准版本的近邻数；没有发布版本的基材回退到录入参数（默认 3）。结果逐行记录近邻数来源、所用称重档案、盲评母批与盲评误差，计算单同时保存校准快照，配方参考页与导出 CSV 均可追溯。

录入参数 **纳入参考的近邻数**，默认 3，允许范围 1–8，仅在该基材没有已发布校准版本时作为兜底口径。每个待试配样只查同基材的合格历史记录。增加近邻数会改变配方参考中心。

演示集 `yudian_compound_20261125.csv` 由 `backend/src/business/demo.py` 用固定数据或固定随机种子生成：两个基材各 8 个母批、每批 5 个分装子批（共 80 条归档子批，其中 10 条磨耗未通过），外加 1 条 EPDM 金样 RG-H-001 与 8 条待试配记录。工作台保留每次运行使用的输入版本、参数、结果和签审人。业务判断由服务端执行，前端图表直接读取返回的数值。

## 一天的工作剧本

1. 08:15，收配员拿到 yudian_compound_20261125.csv，内有两个胶粒基材各 8 个母批、81 条归档子批（含金样 RG-H-001）与 8 条待试配记录。
2. 08:30，品控员确认 RG-H-041 的配比虽然碰巧与旧金样相同，但磨耗验收未通过。
3. 08:45，分析员在近邻校准页用最新称重档案创建校准：再生 EPDM 盲评通过进入待发布，再生 SBR 盲评误差高于默认 3 近邻被标记为未通过，继续保留旧版口径。
4. 09:00，复核员核对盲评母批与误差后发布 EPDM 校准版本；打样师录入 RG-T-01 的 92 / 40 / 36 / 32 g 目标比例，并把新样板标为 750 g。
5. 09:10，提交试配单：EPDM 目标按已发布的 4 近邻计算，SBR 目标仍按默认 3 近邻兜底，RG-T-01 命中既有合格样 RG-H-001，配比距离为 0。
6. 09:25，打开 RG-T-02 的四色偏差与配方参考页溯源信息，确认所用档案、近邻数和盲评误差。
7. 09:40，导出配方参考单，给首试样领取 345 / 150 / 135 / 120 g 四色橡胶。
8. 10:30，品控用实物样板复测色差与磨耗，再决定是否确认批量生产；补录新称重档案期间旧版推荐不受影响。

## 快速启动

```sh
test -f .env || cp .env.example .env
docker compose config --quiet
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

前端在 `http://127.0.0.1:18321`，API 文档在 `http://127.0.0.1:19321/docs`，数据库绑定 `127.0.0.1:17821`。重复运行种子命令保留已有账号和版本。测试验收后用 `docker compose down` 停机可保留数据卷。重置本地演示数据可用 `docker compose down -v --remove-orphans`。

## 技术与配置

| 服务 | 技术与职责 |
|---|---|
| frontend | HTML/CSS/JS ES 模块，Nginx 静态页面与同源 API |
| backend | Python 3.11、FastAPI、SQLAlchemy、JWT |
| worker | Python 后台进程，使用 DB 的原子认领、租约与重试，输出 CSV |
| db | MySQL 8.0，存账号、版本、计算单和审计 |
| redis | Redis 7，通知 worker 尽快拾取，任务状态由数据库持久化 |

`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` 管理回环端口，`JWT_SECRET` 为签名密钥，`DB_PASSWORD` 为应用数据库口令，`DB_ROOT_PASSWORD` 为数据库 root 口令，`COMPOSE_PROJECT_NAME` 控制该栈的命名空间。

本地 Python 开发可用 `docker compose up -d db` 启动关系库，并另起一个仅绑定回环的 Redis。Compose 内的 Redis 通过容器网络连接。用 Python 3.11 安装 `backend/requirements.txt` 后，进入 backend 目录，设置 `DATABASE_URL`、`REDIS_URL`、`JWT_SECRET`、`ARTIFACTS_DIR`、`SEED_DEMO`，分别运行 `uvicorn src.main:app --reload`、`python -m src.worker`。ARTIFACTS_DIR 需已存在且由两进程共享。前端可使用 Compose Nginx 镜像并重建以加载修改，或用已有 Nginx 反向代理本地 Python 端口。

`backend/src/business/` 保存本题字段、生成器和算法，`backend/src/services/` 处理资源生命周期，`backend/migrations/` 是初始关系模式，`frontend/src/` 按页面、API、会话、组件、路由及样式组织。前后端枚举分别在 `backend/src/constants/workflow.py` 和 `frontend/src/constants/enums.js`。角色用于 JWT 路由与表单权限，计算状态用于队列与结果页，签审决定用于交接页、审计和签发导出。
